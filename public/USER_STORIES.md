See the Cases and expected observations table in the repository README. Executed results belong in the dedicated host evidence folder, not this source document. For payment-unavailable, missing traces alone do not qualify the result: the harness records one exact checkout dispatch, the HTTP error/no-order response and a successful cart readback; CI additionally requires an exported checkout error span carrying that synthetic shopper ID. An unavailable, stale, malformed, or wrong-shopper readback remains unknown and cannot turn an unsuccessful assessment into an observed result. The pinned Cart service serializes an empty default cart without a `userId`; those readbacks are labeled `NOT_ECHOED_FOR_EMPTY_CART`, not identity-confirmed. Non-empty cart readbacks must echo the requested synthetic shopper. `shared-cart-conflict` uses two sequential clients; `shared-cart-overlap` uses two separate client processes and only claims overlapping client request windows when the measured intervals overlap. Neither actor labels nor client timing prove application identity or overlap inside the service handler. CI also stops and restarts the same recorded overlap project and verifies the same cart through the HTTP API before exercising fresh-world reset/replay. This product does not establish settlement, fulfillment, durable deduplication, safe retry, application authorization, or independent Valkey truth.
