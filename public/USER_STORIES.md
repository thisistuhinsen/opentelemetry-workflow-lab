See the Cases and expected observations table in the repository README. Executed results belong in the dedicated host evidence folder, not this source document. For payment-unavailable, missing traces alone do not qualify the result: the harness records one exact checkout dispatch, the HTTP error/no-order response and a successful cart readback; CI additionally requires an exported checkout error span carrying that synthetic shopper ID. An unavailable or wrong-shopper cart readback remains unknown. The pinned Cart service serializes an empty default cart without a `userId`; those readbacks are labeled `NOT_ECHOED_FOR_EMPTY_CART`, not identity-confirmed. Non-empty cart readbacks must echo the requested synthetic shopper. The shared-cart-conflict case launches two separate sequential clients against one synthetic user/cart and records both raw responses; harness actor labels are not application identities, and the case makes no overlapping-concurrency claim. This product does not establish settlement, fulfillment, durable deduplication, safe retry, or application authorization.
